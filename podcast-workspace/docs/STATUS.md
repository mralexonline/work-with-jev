# Status: what works, what does not, and the gated path to production

Last verified: see [VERIFICATION.md](VERIFICATION.md) (generated by `scripts/verify_e2e.py`). Nothing below the "Working" heading
has been run against a paid service, because no account or credential was available while building.

## Working (tested on real inputs, US$0)

* Chat → project plan → free job: brief parsed (duration, hosts, quoted bottom-left text), pre-flight blocks impossible plans.
* Script (template writer, ≤ 60 s) → Kokoro-82M voices → shot plan with wide + two close-ups → captions (ASS/SRT) → ffmpeg
  assembly → bottom-left **“Durham & Clarington Community REAL TALK”** on every sampled frame → ffprobe-verified H.264/AAC MP4.
* Mouth movement driven by each host's real audio energy (checked: high only while that host speaks); idle blinking, breathing,
  sway, gestures, listener nods; slow push-ins on every shot.
* Persistent queue, leases, bounded retries, `kill -9` crash → resume with cached shots, cancel mid-render with no stray ffmpeg
  processes or `.part` files, progress + SSE logs, browser can be closed and reopened.
* Auth, redaction, same-origin checks, owner-only terminal with scrubbed environment, media whitelist.
* Spending: caps, approval gate, reservation, per-call guard, usage ledger, estimator that switches from ASSUMED to measured.
* Browser UI driven by headless Chromium (login, plan card, start, progress, result, tabs, terminal). In-browser video *playback* could not be tested there: the sandbox Chromium lacks H.264; the MP4 is verified by ffprobe and HTTP Range instead.
* HF search + inspect, licence classification, dependency parsing, hardware estimate, registry matching, adapter scaffolding
  (against mocked HTTP; HF endpoints also read live for the registry facts).

## Implemented but never run against the real thing

* `openai-compatible` and `anthropic-api` script writers — exercised only against a local mock HTTP server (request shape,
  JSON/markdown cleanup, checkpoint resume). Real model output quality and 20-minute continuity are unknown.
* GitHub search/inspect — mock-tested; the GitHub API was not reachable from the build sandbox for arbitrary repositories.
* `ModalClient` (spawn/poll/cancel/usage recording) and `cloud/modal_app.py::download_weights` — import-checked only (loading `cloud/modal_app.py` under `modal==1.6.1` caught and fixed a real decorator bug; nothing was deployed or run).

## Known weaknesses of the working path

* The draft video is a **flat cartoon**, not a "realistic" podcast. It is deliberately labelled `draft_quality`.
* Captions are proportionally timed, not word-aligned.
* Kokoro has a fixed voice pack: pleasant, but obviously synthetic, no cloning, no laughs/breaths.
* The template writer's dialogue is generic filler. Real content needs an LLM.
* Speaking rate (~2.6 words/s) is calibrated on Kokoro only; with other TTS the script length will differ from the target.
* CPU draft rendering of a long episode is slow (roughly 1–2× real time on 4 cores); it is checkpointed but not fast.

## Gated path to 15–20 minute production (do not skip gates)

| Gate | Goal | Pass criteria | Cost to try (my suggested cap) |
|---|---|---|---|
| 0 | Free proof | all `verify_e2e.py` checks pass | US$0 — **done** |
| 1 | **30-second GPU proof** | one 30 s clip with real photoreal hosts: FLUX stills for Matt/Chloe/studio → InfiniteTalk (or S2V) per close-up → assembled by the existing path. Pins the real command lines, VRAM, cold-start and GPU-s per output-s | ~US$10 cap: weight download (CPU), image build, 2–4 attempts. **Needs your approval + Modal account.** |
| 2 | Quality + cost review | you judge identity consistency, lip-sync, motion, wide-shot realism; measured GPU-s/output-s feeds the estimator; decide hybrid vs fully generative | a 2–3 minute test, ~US$5–15 depending on Gate 1's measurement |
| 3 | Full episode | estimator `high` ≤ remaining budget, approval with a cap, run with checkpoints; review before anything is shared | whatever Gate 2 says; one 20-min episode may consume most of a month's budget |

Risks to resolve at Gate 1/2: wide shots with two people talking are hard for audio-driven models (may need per-person clips
composited, or a static/low-motion wide); identity drift across a 20-minute run; per-call cold starts; VRAM for 14B models.
